# Data Sentinel - AI-Powered Data Quality & ML Readiness Platform

**Data Sentinel** is a data profiling, quality assessment, and machine learning readiness platform designed to help users understand the structure, reliability, and usability of their datasets before using them for analytics or machine learning.

Upload a CSV or Excel dataset to generate a comprehensive profile, detect potential data quality issues, calculate a quality score, assess ML readiness, and explore findings through an interactive Plotly dashboard. An AI-assisted explanation layer translates technical findings into understandable insights and actionable recommendations.

The platform follows a **deterministic-first architecture**: the Python quality engine performs the actual analysis, while the AI assistant explains the findings. This keeps reported counts, detected columns, and calculated metrics grounded in the analysis results rather than generated by an LLM.

## Overview

Poor data quality can lead to misleading analytics, unreliable dashboards, and inaccurate machine learning predictions. Missing values, duplicate records, inconsistent categories, unexpected numerical values, and potential sentinel values can compromise downstream workflows.

Data Sentinel helps identify and understand these issues before a dataset is used for analysis or model development.

The platform combines deterministic Python-based analysis, statistical anomaly detection, ML readiness assessment, interactive visualizations, and AI-assisted explanations in a single workflow.

### Core Workflow

**Upload → Profile → Detect → Assess → Visualize → Explain**

1. **Upload:** Provide a CSV or Excel dataset.
2. **Profile:** Inspect dataset dimensions, column types, distributions, and other available statistics.
3. **Detect:** Run the deterministic data quality engine to identify potential quality issues.
4. **Assess:** Calculate the dataset quality score and evaluate machine learning readiness.
5. **Visualize:** Explore results using the interactive dashboard.
6. **Explain:** Obtain understandable descriptions of findings and recommended next steps.

## Key Features

### 1. Dataset Profiling

Generate an overview of the uploaded dataset to understand its structure and characteristics.

Depending on the dataset and the implemented profiling checks, this can include:

- Number of rows and columns.
- Column names and inferred data types.
- Numerical and categorical column summaries.
- Descriptive statistics and distributions.
- Missing-value statistics.
- Dataset-level and column-level quality information.

### 2. Data Quality Detection

The deterministic quality engine analyzes the dataset for supported data quality issues.

The current implementation includes checks for:

- **Missing values:** Identify null or missing entries.
- **Duplicate records:** Detect duplicate rows or records according to the implemented duplicate-detection rules.
- **Categorical inconsistencies:** Identify potentially inconsistent representations of categorical values.
- **Sentinel values:** Detect values that may represent special missing-data markers, such as `-9999`, where supported by the detection logic.
- **Numerical anomalies:** Apply Isolation Forest to eligible numerical columns to identify potential anomalous observations.

Detection results depend on the implemented checks, data types, dataset characteristics, and configured eligibility rules. A detected anomaly is not necessarily an error, and a suspected sentinel value is not automatically proof of missing data.

### 3. Data Quality Score

Data Sentinel provides a dataset-level quality score intended to summarize the results of its supported quality checks.

The score helps users identify potential data quality concerns and prioritize further investigation.

The score should be interpreted according to the platform's implemented scoring formula and included checks. It is not a universal guarantee that a dataset is correct, complete, or suitable for every analytical task.

### 4. Machine Learning Readiness Assessment

The platform evaluates data quality characteristics relevant to preparing a dataset for machine learning.

The assessment can help users understand issues that may require attention before model development, including missing data, feature suitability, numerical anomalies, and other supported quality indicators.

ML readiness is an assessment of the dataset's observed characteristics, not a guarantee of model performance. Actual readiness also depends on the prediction objective, target definition, feature leakage, sampling strategy, and validation methodology.

### 5. Interactive Dashboard

The frontend presents analysis results through an interactive dashboard with Plotly-based visualizations.

Users can explore the findings and inspect the results returned by the backend without relying exclusively on raw console output.

The exact visualizations and available interactions depend on the current frontend implementation.

### 6. AI-Assisted Explanations

Data Sentinel includes an AI assistant that explains data quality findings and provides recommendations for investigating or addressing them.

The assistant supports two explanation modes:

- **Rule-based mode:** Generates explanations using predefined logic without requiring an external LLM API.
- **LLM-assisted mode:** Uses Google's Gemini API, when configured, to improve the wording and readability of explanations.

The AI layer is designed to explain findings produced by the Python analysis engine rather than independently determine the underlying data quality metrics.

### 7. CSV and Excel Support

The analysis API accepts CSV and Excel files in the supported formats:

- `.csv`
- `.xlsx`
- `.xls`

Large CSV files can use a chunked processing path when the applicable processing conditions are met.

Excel files follow a separate processing path and may require conversion before large-file processing.

## How It Works

Data Sentinel separates analysis from explanation.

### Analysis Layer

The Python backend receives the uploaded dataset and executes the applicable profiling, quality detection, scoring, and ML readiness logic. Statistical anomaly detection is applied to eligible numerical columns under the configured execution conditions.

### Presentation Layer

The frontend requests analysis results from the API and displays them through the dashboard and supported visual components.

### Explanation Layer

The explanation endpoint receives structured findings and generates human-readable explanations and recommendations. When a Gemini API key is configured, the LLM-assisted path can improve the wording of those explanations.

The intended flow is:

```text
CSV / Excel Upload
        |
        v
     FastAPI
        |
        v
 Dataset Profiling
        |
        v
 Deterministic Quality Engine
        |
        +----------------------+
        |                      |
        v                      v
  Quality Score        ML Readiness
        |                      |
        +----------+-----------+
                   |
                   v
          Structured Findings
                   |
          +--------+--------+
          |                 |
          v                 v
   Rule-Based Mode     LLM-Assisted Mode
          |                 |
          +--------+--------+
                   |
                   v
       Interactive Dashboard
```

## Installation and Setup

### 1. Obtain the project

Clone the repository if it is hosted on GitHub:

```bash
git clone <YOUR_REPOSITORY_URL>
cd <YOUR_PROJECT_DIRECTORY>
```

Alternatively, extract the project ZIP and open the extracted folder in your terminal or editor.

### 2. Create a virtual environment

**Windows PowerShell:**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks script activation, use the virtual environment's Python directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**Linux or macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

With the virtual environment activated:

```bash
python -m pip install -r requirements.txt
```

If dependency installation fails, check the Python version, package compatibility, and error message before upgrading or replacing dependencies.

### 4. Configure environment variables

If the project uses an `.env` file or environment-based configuration, follow the application's configuration requirements.

For optional Google Gemini API access, set `GEMINI_API_KEY` in your environment. Do not commit real API keys or other secrets to version control.

## Running the Application

### 1. Start the backend

From the project root, with the virtual environment activated:

```bash
python -m uvicorn main:app --reload
```

The command assumes that `main.py` exports the FastAPI instance as `app`. If your instance uses a different name, replace `app` with the actual exported variable.

The API should be accessible at:

- API base URL: `http://127.0.0.1:8000`
- Interactive API documentation: `http://127.0.0.1:8000/docs`
- Alternative API documentation: `http://127.0.0.1:8000/redoc`

The documentation pages are available if enabled by the application configuration.

### 2. Start the frontend

**Option A - Open directly**

Open `frontend/index.html` in your browser if the frontend supports direct file access and its API requests work from that context.

**Option B - Serve the frontend locally**

From the project root, run:

```bash
python -m http.server 5500 -d frontend
```

Then open:

`http://127.0.0.1:5500`

Serving the frontend over HTTP is generally preferable when the browser or application requires normal HTTP origin behavior.

If the frontend cannot communicate with the backend, verify the configured API base URL and the backend's CORS settings.

## API Reference

The application exposes the following documented endpoints.

### `GET /api/health`

Checks the application's health endpoint.

**Example:**

```bash
curl http://127.0.0.1:8000/api/health
```

The exact response fields depend on the implementation.

### `POST /api/analyze`

Analyzes an uploaded dataset and returns the analysis results.

**Supported formats:** CSV, XLSX, XLS.

**Purpose:**

- Load the uploaded dataset.
- Run supported profiling and quality checks.
- Calculate applicable quality and ML readiness metrics.
- Return structured analysis results for the frontend.

For very large CSV files, the application can use chunked processing when the relevant conditions are met.

**Important:** The exact multipart field name, accepted parameters, response schema, and file-size constraints must be confirmed in the API implementation or at `/docs`.

### `POST /api/explain`

Generates explanations and recommendations from structured findings.

**Purpose:**

- Explain detected quality issues.
- Translate technical results into readable descriptions.
- Recommend potential next steps.
- Use the configured rule-based or LLM-assisted explanation path.

The explanation layer should not be treated as a substitute for the deterministic analysis results.

## AI Assistant

The AI assistant is an explanation layer built around findings produced by the analysis engine.

### Rule-Based Mode

When no Gemini API key is configured, the application can use its supported rule-based explanation logic.

This mode avoids an external LLM API dependency for explanation generation, provided the rest of the application and its dependencies are available locally.

### Optional Google Gemini Integration

If the application is configured to use Google's Gemini API, provide an API key through the environment.

**Windows PowerShell - current terminal session:**

```powershell
$env:GEMINI_API_KEY = "YOUR_API_KEY"
```

**Linux or macOS:**

```bash
export GEMINI_API_KEY="YOUR_API_KEY"
```

Restart the backend after configuring the environment variable.

These commands set the key for the current terminal session. For persistent or team-based configuration, use an appropriate secrets-management approach and follow the application's configuration implementation.

API access is subject to Google's Gemini API eligibility, available quotas, usage limits, and applicable pricing. The optional LLM mode is not guaranteed to be free.

### Trust and Accuracy

The Python engine is responsible for calculating data quality metrics and producing the underlying findings. The LLM is intended to improve explanation wording and communicate recommendations.

Users should verify important recommendations against the original data and the application's reported metrics before applying changes.

## Large Dataset Processing

Data Sentinel includes a chunked CSV processing path for large files, subject to the conditions implemented by the backend.

The original application documentation identifies the following behavior:

- CSV files of at least 100 MB use chunked CSV processing.
- Large Excel files may be converted to CSV before subsequent processing.
- Very large Excel files may take considerably longer to process.

Chunked processing can reduce peak memory requirements for some workflows, but it does not automatically make every analysis step memory-efficient. Profiling, duplicate detection, anomaly detection, sorting, intermediate data structures, or result aggregation may still consume substantial memory.

Actual processing limits depend on the file format, hardware, implementation, and enabled quality checks.

For large datasets, test representative files and monitor execution time and memory consumption before processing production data.

## Security and Privacy

Before using Data Sentinel with sensitive or production datasets, consider the following:

- Do not commit API keys, passwords, or secret configuration files.
- Keep `.env` files out of public repositories and provide a sanitized `.env.example` when needed.
- Validate uploaded file types and handle malformed or unexpectedly large files safely.
- Treat uploaded datasets as untrusted input.
- Verify where uploaded data is processed before using confidential information.
- When Gemini integration is enabled, review the information sent to Google's API and the provider's applicable data policies.
- Do not assume that local execution automatically provides authentication, authorization, encryption, or secure multi-user isolation.

The current application should not be considered production-secure merely because its analysis engine runs locally.
